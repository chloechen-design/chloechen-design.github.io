Overview

The product turns experience into a reusable source of truth.

After years of product work, the hard part of interview preparation was recalling an exact decision, connecting it to a new question, and keeping the answer accurate in English or French. I reframed preparation as an information and trust problem.

Core design question

How might an assistant help someone retrieve and express their own experience without replacing facts with fluent fiction?

01 / Problem

The material existed. Its retrieval path did not.

Project facts, reflections, draft answers and language practice lived in different places. One experience could support several questions, yet writing an isolated answer for each prompt made the original evidence harder to trace. AI introduced another risk: a paragraph could sound convincing while changing a fact or my voice.

02 / Product model

Store the story once. Compose for the question later.

A project memory holds the situation, constraints, actions, artifacts and limits. A story angle selects what matters for a question. A language version changes the expression, never the underlying claim.

04 / AI-native practice

Use AI twice, with a deliberate handoff each time.

AI plays two different roles here: Codex helps turn product intent into a browser prototype; an in-product assistant could suggest story angles or phrasing. They need different checks. Neither decides whether a personal claim is true.

01
DESIGN × BUILD

AI as prototype partner

  1. Frame the job

    Define task, source model, privacy boundary and success behavior before prompting.

  2. Specify behavior

    Describe states, content rules and failures; ask Codex for a testable slice.

  3. Inspect the browser

    Try the sequence, break edge cases, review layout and keyboard access, then revise.

  4. Record decisions

    Document changes, assumptions and what the prototype cannot validate.

02
PRODUCT × USER

AI as optional assistant

  1. Retrieve before generating

    Find an appropriate memory or angle grounded in stored facts.

  2. Draft within boundaries

    Change language or tone while preserving source, scope and unknowns.

  3. Expose uncertainty

    Flag unsupported claims instead of producing confident prose.

  4. Return control

    Let the user edit, reject, compare, export or keep practicing.

Operating principleHuman sets the goal → AI proposes → human checks against evidence → product records the decision.

This is the methodology guiding the design, not a claim that every proposed AI feature has been implemented or tested. The public walkthrough is scripted.

05 / Design decisions

Trust lives in the interface, not a disclaimer.

01 ⌕

Separate fact, framing and phrasing.

Store the project event once and let question angles reuse it. This makes corrections traceable to the source instead of scattered among answers.

UI consequence → Source memory / chosen angle / editable answer
02 ◇

Make readiness a review state.

Draft, fact check, voice check and ready show what work remains. Generated text does not silently become verified.

AI draftFact checkVoice checkReady
03 ↔

Translate expression, preserve meaning.

English and French versions share a source story and verification state. Language practice cannot add an outcome absent from the original.

UI consequence → Language switch belongs to the answer layer
04 ◈

Protect the private corpus.

Public examples use synthetic content. Architecture and motion can be shown without publishing personal application material.

UI consequence → Demo is visibly labeled as simulation
06 / Evaluation

A credible prototype also names what remains to prove.

The available portfolio material shows a browser interaction, a content model and a design rationale. It does not establish AI accuracy, interview performance, adoption or production deployment.

↗USABILITY

Can people retrieve a story?

Try an unfamiliar prompt and observe whether a user finds a relevant source and explains the match.

Next measure: completion and wrong-story selections.
✓TRUST

Can they catch a false claim?

Seed a draft with one altered fact. Check whether the source and review states help them correct it.

Next measure: detection and correction rate.
✳VALUE

Is preparation easier?

Compare repeated preparation sessions with notes alone and with the prototype.

Next measure: time to credible answer and edit burden.
